## Level 1.1 — 计价与输出

**这一关唯一的新东西：把一整行输入切开。**

示例要求：

```
> 001
Cola 3.50
> 001 003
Cola 3.50
Noodles 6.00
> 004
ERROR: code not found
> prices
Item No. Pri.
-----------------
Cola 001 3.50
Lollipop 002 0.50
Noodles 003 6.00
> exit
```

### 要解决的小问题（自己先想，想不出来再看提示）

| # | 问题 | 提示 |
| --- | --- | --- |
| 1 | 怎么读一整行，而不是读到空格就停？ | `scanf("%s")` 读到空格就断，一行里多个条码会被拆成多次循环。用 `fgets` 读整行。 |
| 2 | `fgets` 读进来的行尾有个 `\n`，怎么去掉？ | 找到第一个 `'\n'` 或 `'\r'`，把它改成 `'\0'`。不处理的话 `"001\n" != "001"`，查表永远失败。 |
| 3 | 怎么把 `"001 003"` 拆成 `"001"` 和 `"003"`？ | `strtok(line, " \t")`，循环调到返回 `NULL` 为止。 |
| 4 | 商品表怎么存？ | `struct Item { char code[8]; char name[32]; double price; };` 装进数组。三个商品，线性查找完全够用（`for` 循环 `strcmp`）。 |
| 5 | 价格为什么用 `double` 而不是 `float`？ | 钱用 `float` 精度不够。后面会讲更稳的做法（存"分"用 `int`）。 |
| 6 | 格式化输出怎么对齐？ | `printf("%-12s %-6s %.2f\n", ...)`，`-` 表示左对齐，数字是宽度。`%.2f` 保证 `3.5` 打成 `3.50`。 |
| 7 | `exit` 和 `quit` 怎么退？ | 在循环里 `break`，或者把循环条件做成一个 `running` 标志位。 |

### 建议的骨架（自己写，别抄我的）

```c
/* pos.c —— 主循环长这样，剩下你自己填 */
int main(void) {
    char line[256];
    while (1) {
        printf("> ");
        fflush(stdout);              /* 提示符必须马上出现，不然用户以为卡死了 */
        if (fgets(line, sizeof line, stdin) == NULL) break;   /* Ctrl+Z / Ctrl+D */
        trim_newline(line);
        if (line[0] == '\0') continue;                        /* 空行直接忽略 */

        char *tok = strtok(line, " \t");
        if (tok == NULL) continue;

        if (strcmp(tok, "exit") == 0 || strcmp(tok, "quit") == 0) break;
        if (strcmp(tok, "prices") == 0) { cmd_prices(); continue; }

        /* 其余情况：当成条码，而且可能不止一个 */
        for (; tok != NULL; tok = strtok(NULL, " \t")) {
            handle_barcode(tok);
        }
    }
    return 0;
}
```

**`fflush(stdout)` 这行别省**——管道/重定向下 stdout 是块缓冲的，不 flush 提示符会跟输出粘在一起。

### 验收标准（自己测）

- [ ] `001` → `Cola 3.50`
- [ ] `001 003` → 两行
- [ ] `004` → `ERROR: code not found`
- [ ] `prices` → 表头 + 分隔线 + 三行商品
- [ ] `exit` 退出，退出码是 0
- [ ] 输入空行、只输入空格、输入 `001  003`（多个空格）、`001 003 001` 都不崩

## Level 1.2 — 订单结账

示例要求：

```
> 001 001 002
Cola 3.50 x2 =7.00
Lollipop 0.50 x1 =0.50
> -001
Cola 3.50 x1 =3.50
> checkout
Receipt
Item Pri. Qty Amount
-----------------------
Cola 3.50 x1 =3.50
Lollipop 0.50 x1 =0.50
-----------------------
Total =4.00
```

### 新增的坑

1. **`-001` 里的减号**：`-` 单独一个字符，注意 `strtok` 的分隔符里**不能**放 `-`（放了就切不出来了）。判断 `tok[0] == '-'`，然后拿 `tok + 1` 去查表。
2. **这是个"购物车"，不是"小票历史"**。同一次 `checkout` 之前，同一个条码只出现一行，数量累加。所以每次扫到条码都要先"在购物车里找有没有"，有就 `qty++`，没有就新增一行。
3. **`-001` 把数量减到 0 怎么办？** 从购物车里删掉这一行（而不是留一行 `x0`）。
4. **打印时机**：示例里每扫一个条码都有输出，但输出的是**该商品在购物车里的当前状态**（`x2` 是累计后的）。所以"记录 +1"和"显示"是一回事，显示的是购物车里的总数。
5. **`checkout` 的金额要准**。`0.5 + 3.5` 打印 `4.00`，用 `double` 打 `%.2f` 基本没问题，但心里要清楚浮点累加有误差。

### 验收标准

- [ ] 连续扫同一商品数量会累加
- [ ] `-001` 减到 0 之后该行消失
- [ ] 购物车空时 `-001` 不出错（提示一下就好）
- [ ] `print` 和 `checkout` 的表头/分隔线跟示例一致
- [ ] `drop` 之后 `print` 是空小票
- [ ] `checkout` 之后购物车被清空

## Level 1.3 — 当日销售统计（第一次碰文件）

### 拆成两半

**写**：每次 `checkout` 把这一单追加进文件。关键点：

- `fopen(path, "a")` —— `"a"` 就是 append，不会覆盖历史。
- 写完立刻 `fclose`。别攒着，程序被 Ctrl+C 杀掉时缓冲区里的东西就没了。
- **一次一条记录**，字段里不要出现逗号，否则 CSV 就烂了。

建议的 `sales.csv` 设计（自己想清楚再定，这决定了后面好不好写）：

```
date,no,time,total,items
2026-03-01,1,10:15:32,4.00,Cola x1;Lollipop x1
2026-03-01,2,11:02:10,12.00,Noodles x2
```

明细塞在一个字段里、多种商品用 `;` 隔开，读的时候再切一次。这样做的好处是**一单一行**，聚合好写。

**读**：`sales [day]` 要把文件里当天的记录读出来，逐行解析，最后求和。

- `fgets` 逐行读 → `strtok` 或 `sscanf` 切字段 → 比较日期 → 累加。
- 没给参数时"默认今天"。**时间怎么拿？** `#include <time.h>`：

```c
time_t t = time(NULL);
struct tm *lt = localtime(&t);
char date[11];                  /* "YYYY-MM-DD" */
strftime(date, sizeof date, "%Y-%m-%d", lt);
char clock[9];                  /* "HH:MM:SS" */
strftime(clock, sizeof clock, "%H:%M:%S", lt);
```

### 最容易翻车的地方：Date: 1 是什么意思？

示例里 `sales` 打出的是 `Date: 1`，`newday` 之后变成 `Date: 2`。这是**第几个营业日**，不是日历日期。

所以你需要额外持久化一个"今天是第几天"的计数器（比如 `state.txt` 里存个数字），
否则程序一重启，"第几天"就丢了，`sales 1` 也就查不到东西。

**`newday` 的两个说法**：题目允许"文件另存为带日期的文件"或者"清空文件但保留历史文件"。选一个，写进日志说明理由。

### 验收标准

- [ ] `checkout` 后 `sales.csv` 多一行，重启程序后记录还在
- [ ] `sales` 显示今天的流水 + `Daily: 总额`
- [ ] `newday` 后 `sales` 是空的，`sales 1` 还能查到昨天的
- [ ] 文件不存在时 `sales` 不崩（第一次运行就是这种情况）

## Level 2.1 — 管理员价格管理

**新东西：模式（mode）。** 你不再只有一层循环了，而是"普通模式"和"admin 模式"。

```c
int admin = 0;
while (1) {
    printf(admin ? "admin> " : "> ");
    ...
    if (admin) { /* 认 setprice/itemadd/itemdel/back，其余报错 */ }
    else       { /* 认 admin/prices/条码，其余报错 */ }
}
```

要处理的细节：

1. **读密码**。简单做法：`fgets` 读一行再 `strcmp(secret, "admin123")`。要 `#include <string.h>`。
   想更专业可以用 `<conio.h>` 的 `getch()` 打星号（Windows 专属，不跨平台）。
2. **`itemadd` 要能加进内存里的商品表**。数组开多大？`#define MAX_ITEMS 128`。
3. **`itemdel` 后数组怎么处理的？** 三种做法：把后面的往前挪（保持紧凑）、把最后一个换到空位、或者标记为"已删除"。选一个并说清理由。
4. **`%-6s` 对齐**：加了库存之后表头会变成 `Item No. Pri. Stock`，列宽要跟着调，否则错位。
5. **持久化**：改完价格就没了？重启要还在的话得写回 `items.csv`。

### 题目提示的答案（先自己答，再对照）

> 改了商品价格之后，过往小票记录应该变化吗？

**不应该。** 小票是"当时成交的事实"，是历史凭证。如果价格一变历史营业额就跟着变，
账就对不上了。所以小票里存的是**成交时的单价快照**，不是"去商品表里现查"。
—— 这也意味着 `sales.csv` 里必须存下单时的价格或金额，不能只存条码和数量。

## Level 2.2 — 库存

给 `struct Item` 加一个 `int stock;`，加两个命令。

真正难的不是加法，是**库存和结账的交互**：

- 库存 0 还能不能扫码？能扫，但结账时要拦住。
- 购物车里 5 个，库存只剩 3 个，`checkout` 怎么办？整个单子拒绝，还是只卖 3 个？
  题目没规定 → **你来定规则，并把它写进日志和 README**。这就是所谓的"工程决策"。
- `restock` 之后库存要不要立刻写回文件？
- 结账成功要不要扣库存？扣了之后 `setstock` 盘点又是什么语义？

### 验收标准

- [ ] `restock 001 5` 之后 `prices` 里库存真的变了
- [ ] `setstock 001 0` 之后结账会被拦住（或者按你定的规则处理）
- [ ] 重启之后库存还在

## Level 3 — 自由发挥（挑 1–2 个做深，比全做浅好）

**打折 / 组合销售**
- 第 2 件半价：注意"半价"作用在哪一件上，金额怎么算。
- 满 20 减 5：小票上要**显示出来**优惠了多少，否则顾客看不懂。
- 组合价：可乐+棒棒糖 = 3.80。
- 想清楚"打折是在加购物车时算，还是结账时算"——后者更接近真实 POS，因为要整单算。

**多日报表**
- 读整个 `sales.csv`，按天分组汇总。数据结构：日期 → 总额。少量数据用数组线性扫就够了。

**图形化统计**
- 终端里用 `#` 画柱状图：`Noodles  ############ 12.00`。
- `占比 = 金额 / 总额`，乘上柱子的最大宽度（比如 30），再 `for` 循环打 `#`。

**其他能加分的方向**：退单/退货、`help` 命令、命令历史、参数校验、单元测试、`make test`。
