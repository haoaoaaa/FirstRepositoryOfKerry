## 0. 环境（已在本机验证通过）

本仓库内置了一份免安装的 GCC，就在你自己的工作区里：

| 东西 | 路径 |
| --- | --- |
| 编译器 | `_tools\toolchain\w64devkit\bin\gcc.exe` （GCC 14.1.0） |
| 通用编译脚本 | `cc.cmd` |
| 编译+运行脚本 | `build.cmd` |
| 在线备用（本机连不上时会用） | `_tools\wandbox_compile.py` |

**关键坑（记住这个，能省你两小时）**：w64devkit 的 `gcc` 要靠 `PATH` 找到 `as.exe` / `ld.exe`。
如果你直接用绝对路径调 `gcc.exe`，会报：

```
gcc.exe: fatal error: cannot execute 'as': CreateProcess: No such file or directory
```

所以要么用 `cc.cmd`（它已经帮你把 bin 目录塞进 `PATH` 了），要么自己在 PowerShell 里先执行：

```powershell
$env:PATH = "C:\Users\Administrator\Desktop\git\_tools\toolchain\w64devkit\bin;$env:PATH"
```

### 编译并运行一个 C 程序

```powershell
cd C:\Users\Administrator\Desktop\git
.\cc.cmd -Wall -o .\learning\step0_hello\hello.exe .\learning\step0_hello\hello.c
.\learning\step0_hello\hello.exe
```

`-Wall` 的意思是 "warn all"，把所有警告打开。**从现在开始每次编译都带上它**，
警告不是噪音，它是编译器在免费帮你查 bug。

### 代码补全环境（可选）

VS Code 里真正好用的 C 补全来自 `clangd` 扩展，而不是微软自带的 C/C++ 扩展。
如果你要让补全认识这份内置 GCC，可以在 `.vscode/settings.json` 里指向它（这步不急，先跑起来再说）。
